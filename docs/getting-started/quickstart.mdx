## 1. Choose an RPC endpoint

Raven supports Ethereum-compatible HTTP(S) and WebSocket (WS/WSS) JSON-RPC
endpoints through Alloy. You may use a local node or a hosted provider.

Set the endpoint once for the current shell:

```bash
export NODE_RPC_URL="http://localhost:8545"
```

## 2. Start Raven

From the workspace root:

```bash
cargo run -p raven -- run --source alloy
```

You can pass the endpoint directly instead:

```bash
raven run \
  --source alloy \
  --rpc-url https://ethereum-rpc.publicnode.com
```

For a WebSocket endpoint:

```bash
raven run --rpc-url wss://eth.drpc.org
```

Raven discovers the remote chain ID, fetches full blocks, and passes normalized
events through the runtime. HTTP(S) endpoints use block-number polling. WS(S)
endpoints use `newHeads` subscriptions for immediate notification plus a slower
safety reconciliation. The CLI's built-in `block-logger` plugin logs each
processed block.

## 3. Stop cleanly

Press Ctrl+C. Raven stops the source task and calls `shutdown()` on each started
plugin before exiting.

## Tune ingestion intervals

The default HTTP polling interval is 4,000 milliseconds:

```bash
raven run \
  --rpc-url http://localhost:8545 \
  --poll-interval-ms 1000
```

The interval must be at least one millisecond. A shorter interval detects new
blocks sooner but makes more `eth_blockNumber` requests.

WebSocket endpoints do not poll every four seconds. They subscribe to new heads
and reconcile the latest height every 30,000 milliseconds by default:

```bash
raven run \
  --rpc-url wss://eth.drpc.org \
  --reconciliation-interval-ms 60000
```

Reconciliation recovers height gaps after a missed notification or reconnect.
A longer interval reduces safety requests but increases the worst-case time to
discover such a gap. Both interval values must be greater than zero.

<Warning>
    The Alloy source currently starts from the latest block observed at startup
    and does not backfill older history. It also emits applied blocks only;
    reorg detection is planned.
</Warning>
